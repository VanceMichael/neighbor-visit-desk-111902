# 互助站与街道登记门户

所有服务都在本机回环地址运行，数据及组织名称均为合成演练资料。重启来源服务会复位演练资料和当次受理记录。

## 运行

使用 Node.js 22.23.4。
本地首次准备时运行 `npm ci` 和 `npx playwright install chromium`。已经配置 Chromium 的环境可以直接复用其浏览器缓存。
运行 `npm start` 启动演练来源，默认地址为 `http://127.0.0.1:3100`，通过 `PORT` 修改端口。
运行 `npm test` 检查来源服务和原始资料。

`requests/example.json` 是业务人员提交的样例请求。
启动后处于演练阶段 0。可向 `POST /replay/phase` 发送 JSON `{"phase":1}` 切换到下一批资料。阶段切换不会清除此前受理的经办号。

## 门户

- `/station` 为互助站服务单。
- `/consent` 为代理授权与转站确认。
- `/street` 为街道探访登记。

门户以浏览器中可见的表格、表单和回执为对接契约。

## 浏览器代办（desk/）

`npm run desk -- --origin http://127.0.0.1:3100 [--request requests/example.json] [--state-dir .desk]`

代办只用 Playwright 操作可见页面（读表格、填表单、读回执 `<pre>`），不调用任何页面未暴露的接口。台账与人工接手报告默认写入 `.desk/`（已忽略）。

业务口径：

- **同一次探访的认定**：个人服务编号只在站点内有效。按「共同探访编号 + 老人 + 日期 + 实际时段」把双人或多份服务单合并为一次街道登记，避免一单变两次。
- **代理授权核对**：按代签人、适用事项、起止时刻逐单核对，授权时刻窗必须完整覆盖实际时段；换人或收窄只影响适用时段。已登记后发现越界的，走街道撤销而不是再登记一次。
- **转站凭证**：老人归属站点之外的服务单视为转站单，必须另有覆盖该时段的连续服务凭证，缺失即停在人工接手位。
- **街道冲突避让**：街道按老人和日期限制同类服务；同日已有独立有效探访（办理号可核实、探访编号不同）只登记避让，不覆盖。
- **回执不可核实**：确认页只有「待显示」时先按经办号查既有记录；仍无法证明成功或失败，该分项停在人工接手位，报告写清两边看到的记录与未执行动作，同单其他分项继续。
- **撤销与回填顺序**：撤销原因和原办理号随撤销提交街道；街道撤销确立前，互助站不标撤销。只有街道办理号可核实后，才逐单回填互助站（每份服务单独立经办号，重复运行幂等）。

`npm test` 另含 `test/domain.test.mjs`（规则单测）与 `test/desk.test.mjs`（两阶段端到端：合并登记、待显示挂账、授权收窄撤销、转站补录、回填与幂等）。
